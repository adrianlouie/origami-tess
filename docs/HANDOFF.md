## Gotchas and decisions
- `/next-step` squash-merges the open PR (CI green only; stops if red, pending or ambiguous). Each step's own PR ticks its plan box; write the handoff right after opening the PR and commit it to the same branch.
- Commits and PRs follow `CLAUDE.md`: no `Co-Authored-By: Claude` trailer and no "Generated with Claude Code" footer. This overrides the default attribution reminder, which the harness keeps re-sending.
- TypeScript only. Python is an optional `sympy` scratchpad; Rust→WASM only if the Phase 5 solver is too slow (it is not: 2 to 72 ms on the gadgets).
- Lattice math is exact integers (Eisenstein, `number`, with `checkedMul`/`checkedAdd` throwing past 2⁵³). Floats appear only at the render boundary (`app/render/`, `app/viewer/`) and in `core/simulate/`; the one shared tolerance is `RENDER_TOLERANCE` = 1e-5. The exception is BigInt in `trianglesShareInterior` and `openSegmentMeetsTriangle`, because line intersections are rational. Prettier (`printWidth` 100) is enforced in CI.
- `toCartesian` maps a + bω to (a − b/2, b√3/2); SVG renderers negate y. **ω is at 120°**. `Affine` is z ↦ M·z + t, det M = ±1, `compose(f, g)` applies g first.
- Crease graph: `faces` lists bounded faces only (CCW walks); `holes[i]` holds components nested in `faces[i]`; `rotation[v]` is edge indices CCW from +x. `creasePattern` rejects non-planar input. `noUncheckedIndexedAccess` is on.
- Validators: Kawasaki is exact; Maekawa and Big-Little-Big are necessary only. Gadgets need a "B" frame ring or the validators pass vacuously.
- Solver: `solveMv(cp)` for M/V; `solveClauses(n, clauses)` is the plain-CNF DPLL (model or null; no watched literals). `foldFaces(cp)` returns `ok` or `inconsistent`; `creaseReflection` is an integer map only for 30°-multiple directions, so a random motif with other directions (8.2) will throw.
- Stacking: `stackingClauses(cp, folded)` has one variable per overlapping pair (true = i above j) and six clause kinds. **5.2:** `layerOrder(cp)` returns `ok` (`above`, `order`), `unfoldable` or `inconsistent`. `order` lists every face top first, or is null when every model has a cycle (blocked up to 1000 times). The "top" is the side an unflipped face's front looks toward.
- **Hexagon twists have `order: null`.** Faces 1, 3, 4, 6, 8, 10 form a ring that every valid stacking orders cyclically (no three of them share a point, so transitivity does not apply). This is real, not a bug: blocking the ring makes the formula unsatisfiable, and the blocking clause is implied by any linear order. 5.3 therefore cannot paint faces with one sorted list; it needs an order per region (for example, per cell of the arrangement of folded creases, where the faces over it are totally ordered). Open question for the 5.3 plan.
- The plan's 5.2 acceptance said "valid order" and the first plan said a non-null `order` for the hexagon twists; the test instead requires the relation to pass the oracle and asserts `order` is null with the ring above. Orders are non-null for single vertices and lattice-line arrangements; the symmetric triangle twist (n ≥ 3m) and the hexagon twists are cyclic (`order: null`).
- Test oracles: `foldsFlat` (single vertex, 1D, `core/validate/testing.ts`) and `layerOracle` / `oracleBrokenRules` (whole pattern, float sampling, convex faces; independent of `stacking.ts`). The oracle's old 32-bit bitmask is now a boolean array.
- Verdicts on the shipped gadgets: hexagon twists (1,2) and (2,3) fold; triangle twist folds exactly when n ≥ 3m (`triangleTwist` throws below that; use `rawTriangleTwist` in tests for the unfoldable cases); the star twist folds in its `full` variant (the default) and folds in part, score 50/54, in `partial`.
- **Star twist (5.2c).** The `full` M/V is the table `VVVMMMVV`/`MVMVMMVV`/`VMVMMMMV` per spoke k mod 3 (order a, b, e, g, h, x, y⁺, y⁻), found by search and not by a rule. It is half-turn symmetric, not threefold or 120°-symmetric. The crease set is chiral (`hₖ` is `Tₖ→Qₖ₊₁`, its mirror is not creased), so a mirror image is not a symmetry. 5.1b's "none of 150 folds" was a sampling miss: 2 of 500 sampled half-turn-symmetric assignments fold, at least 6 in all. The layer oracle cannot decide the star outright (435 pairs against its limit of 26), so for `full` it checks the found stacking with `oracleBrokenRules`.
- Enumerating locally valid assignments with `mvSolutions` is slow beyond a few hundred: each solution adds a blocking clause and restarts DPLL, and a first attempt over all 48 free creases ran over an hour without finishing. Tie each edge to its half-turn image to halve the variables, cap the count, and log progress.
- Tests take about 20 s CPU in all (limit 30 s per test). If CI times out, thin the degree-6 samples in `stacking.test.ts` first.
- Environment: macOS `sed` needs `-i ''` and rejects GNU escapes (use python for mutations); there is no `timeout` command; `pkill` is denied by the permission classifier.

- **Near-foldability (5.2d).** A tag is a face (stacking) or vertex (M/V); giving one up drops every clause that mentions it. `minimalConflict` returns *a* minimal conflict, not the smallest: the star twist has a 4-face one ({0, 4, 5, 12}) and the engine reports a 5-face one (20, 21, 23, 24, 27). `minimumRepair` is exact up to 12 tags, else `exact: false`.
- **Locality (5.2e).** Depth uses the sheet topology (a crease with no bounded face on one side), not the "B" label. It is a profile, not one score: how to rank depth, pieces and area is left to 8.2. Whether an edge conflict is acceptable in practice is for the bar-and-hinge simulation (6.2) to say.
- **Viewer (6.1).** World axes are right-handed with +z up; the pattern lies at z = 0 and the start view is from the −y side, 0.6 rad off straight down. The rig is our own (`camera-rig.ts`, no three import), not `OrbitControls`; `fitRig` frames the bounding sphere, so any orbit keeps the pattern in view. Floats are fine in `app/viewer/` (render boundary); the tolerance is still `RENDER_TOLERANCE`. `main.ts` is the only DOM code and is not unit-tested; headless Chrome renders it: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader --window-size=900,700 --virtual-time-budget=4000 --screenshot=<file> http://localhost:5173/` (the Bash sandbox must be off to bind the port). `draw()` is a no-op until a rig exists (a first version threw before the first load). Faces with holes throw in `sheetGeometry`.
- **Simulation (6.2a).** `core/simulate/` is past the exact stages, so floats are allowed there, and `RENDER_TOLERANCE` now lives in `embed.ts` (`app/render/cartesian.ts` re-exports it). Valley is a positive fold angle (wings rise toward +z); the rest state is flat, so fold 0 is flat and fold 1 asks every crease for π. `HingeSpring` has `stiffness` because `k` is already a node of `Hinge`; the two clashed in a first version and the stiffness overwrote the node.
- **Why corner springs.** Bars and hinges alone let a 30-30-120 triangle flatten at about 7% strain and invert, which makes the hinge angle jump by π and leaves no equilibrium (energy rises and bursts, velocity stays near 1e-2). Stiff bars do not cure it. Each triangle corner has an angle spring (`angle` 20); with it every gadget settles at every fold tried. Damping is one global coefficient 2ζ√(k_soft·m), not per node (per-node critical damping took over 240 000 steps).
- **Simulation findings.** Worst strain 4.5% (triangle twist (6, 2), fold 0.5). Hexagon and triangle twists keep every M negative and V positive from fold 0.25. The full star has one nearly flat M crease on the wrong side up to fold 0.5 (edge 41, then 43); the partial star's conflict shows as wrong-side creases (edges 2 and 26 at 0.5). A single vertex can branch: the symmetric right-angle vertex moves to the other rigid branch by fold 0.6, and the sectors 60, 60, 120, 120 vertex does too. Results depend on the path from flat, so `foldSweep` and warm starts matter.
- **Viewer fold (6.2b).** `fold-driver.ts` is pure: `tick(driver, maxSteps)` moves the fold by at most `FOLD_RATE` = 0.02 and warm-starts `relax`; a `done` driver (fold at target and settled) is returned as it is, so `main.ts` runs its `requestAnimationFrame` loop only while not done. The frame budget scales to about 10 ms (100 to 5000 steps) from `performance.now()`. Decided with the user: the camera stays put while folding, `fitRig` on load only. `?gadget=<i>&fold=<percent>` opens a gadget settled through `settle` (up to 400 ticks); the slider animates. **Headless Chrome under `--virtual-time-budget` gets only 3 to 5 animation frames**, so it can screenshot the deep-link state but not the end of an animation; the first load after `npm run dev` starts also reloads for dependency optimisation. Screenshots (hexagon 60 % and 100 %, full star 75 %, triangle (6, 2) 50 %) look right; the slider's 100 % was fold 1 and its coplanar layers z-fought, so 6.3 caps it at `MAX_FOLD` (see the audit bullet). The 6.2a "viewer not looked at after `triangulateFaceKeepingVertices`" item is closed: no gaps. `updateSheet` must recompute bounding spheres (three culls by sphere); a test pins it.
- **Phase 6 audit (6.3) lessons.** Closed: the 6.2a energy item (see `docs/PLAN.md` 6.3 for what the test does and does not detect) and the viewer-after-`triangulateFaceKeepingVertices` check (no gaps). `npx vite-node` was fetched through `npx` for scratch probes only; it is not a project dependency. **three's `LineSegments.computeLineDistances` needs non-indexed geometry** and silently warns otherwise, so a dashed line cannot share the indexed sheet buffer (U lines own a copy). **The viewer's 100 % is fold 0.98** (`sliderToFold`, `foldToSlider`); `parseFoldParam` still returns the slider fraction and `main.ts` maps it. The paper is flat shaded, so there is no normal attribute to refresh. `relax` throws `RangeError("relaxation diverged …")`; `main.ts` stops the loop on it. Vertices with two collinear creases have a straight-crease branch (two creases fold, two stay flat): a path parameter must be a crease that moves on that branch. **Test titles:** a `%` followed by a space in an `it.each` title is read as a format specifier and prints the whole argument; write "percent". On macOS `sed -i` needs `-i ''`. `pkill -f vite` is denied by the auto-mode classifier; a dev server started for screenshots may still be running on port 5173.
- **Phase 5 audit (5.4) lessons.** `stackFaces` blocks at most `MAX_CYCLE_ROUNDS` cycles and still checks the last model. `minimumRepair` weights must be positive safe integers. `fast-check` `.filter` on a tuple that can never pass (n = 1 with `a !== b`) hangs the run synchronously, so `testTimeout` cannot fire. Gadgets run out of memory (unit-edge rays) long before 2⁵³, so overflow is tested with a hand-built rhombus.
