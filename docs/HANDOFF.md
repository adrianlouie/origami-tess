## Gotchas and decisions
- `/next-step` squash-merges the open PR (CI green only; stops if red, pending or ambiguous). Each step's own PR ticks its plan box; write the handoff right after opening the PR and commit it to the same branch.
- Never add a `Co-Authored-By: Claude` trailer to commits, and no "Generated with Claude Code" footer on PR descriptions. This overrides the default attribution reminder, which the harness keeps re-sending.
- TypeScript only. Python is an optional `sympy` scratchpad; Rust→WASM only if the Phase 5 solver is too slow.
- Lattice math is exact integers (Eisenstein, `number`, with `checkedMul`/`checkedAdd` throwing past 2⁵³). Floats appear only in `app/render/`; the one shared tolerance is `RENDER_TOLERANCE` = 1e-5. The exception is BigInt in `trianglesShareInterior` and `openSegmentMeetsTriangle`, because line intersections are rational. Prettier (`printWidth` 100) is enforced in CI.
- `toCartesian` maps a + bω to (a − b/2, b√3/2); SVG renderers negate y. **ω is at 120°**: unit triangles are (a,b),(a+1,b),(a+1,b+1) and (a,b),(a+1,b+1),(a,b+1). `Affine` is z ↦ M·z + t, det M = ±1, `compose(f, g)` applies g first.
- Crease graph: `faces` lists bounded faces only (CCW walks, each face on the left of its directed pairs); `holes[i]` holds components nested in `faces[i]`; `rotation[v]` is edge indices CCW from +x. `creasePattern` rejects non-planar input. `noUncheckedIndexedAccess` is on.
- Validators: Kawasaki is exact; Maekawa and Big-Little-Big are necessary only; `checkLocalFlatFoldability` ignores "F" creases and reports "U" vertices as `unassigned`. Gadgets need a "B" frame ring or the validators pass vacuously.
- Solver: `solveMv(cp)` returns `sat` / `unsat` / `kawasaki`; `solveClauses(n, clauses)` is the plain-CNF version (a model or null). No watched literals; `mvSolutions` restarts per solution (slow on the 48-crease star: thousands of solutions take minutes).
- `foldFaces(cp)` returns `ok` (`transforms`, `flipped`) or `inconsistent`. `creaseReflection` is an integer map only for 30°-multiple directions, so a random motif with other directions (8.2) will throw. Faces with holes, dangling creases and "U" creases throw.
- 5.1b: `stackingClauses(cp, folded)`: one variable per overlapping pair (k-th pair = variable k + 1, true = i above j); six clause kinds (crease, taco-taco, taco-tortilla, tortilla-tortilla, crossing, transitivity). Output is deeply frozen and `folded` is validated against `cp`.
- 5.1b design points that were not obvious: (1) faces are cells, so a face whose interior contains a crease needs its own `crossing` clause; (2) transitivity is emitted only for triples with a common interior point, since three pairwise-overlapping faces may legally be stacked cyclically (pinned by a structural test, because no physical sample exercises it); (3) folds on opposite sides of one line get no clause (the wraps bulge apart and can be shifted off each other in the limit); (4) the code assumes the four faces of two collinear creases are distinct (argued, not proven; a clash would throw "should overlap", not give a wrong answer); (5) taco-tortilla matters only with two F spokes and tortilla-tortilla only on a straight crease with F spokes, so the tests that pin them are in the "ignores flat creases" group.
- Test oracles: `foldsFlat` (single vertex, 1D, in `core/validate/testing.ts`) and `layerOracle` (whole pattern, from the physical picture; convex faces, about 26 overlapping pairs; takes an optional face subset because every constraint is necessary). They were written separately and agree with each other, which is what makes their verdicts on the gadgets trustworthy. Every clause kind was mutation-tested.
- **Verdicts on the shipped gadgets (formula and oracle agree):** hexagon twist (1,2) and (2,3) fold; triangle twist (1,1), (2,1), (1,3) do not, as shipped; star twist (1) does not. Do not assume a gadget folds because it passes the local validators.
- Tests are heavier now (about 19 s CPU from the stacking files; each under 6 s unloaded, limit 30 s). The host had a load average of 14 to 17, which pushed the existing star-twist test past 30 s once; if CI times out, thin the degree-6 samples in `stacking.test.ts` first.
